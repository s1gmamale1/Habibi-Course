# Verified Resources Manifest — Tajweed Course

**Date:** 2026-07-19
**Status:** Canonical. This file is the single source of truth for every external resource (text, audio, font, video, reference data) the course build may use. It supersedes/consolidates the 10 individual research docs in `docs/research/`. Every entry below was cross-checked against the independent curl verification pass (status codes supplied 2026-07-19) plus the research docs' own fetch results.

**How to read the verification status column:**
- **VERIFIED OK** — an independent curl check returned 2xx/200 on this exact URL (or a functionally-equivalent one), or the resource is a code pattern whose concrete instances were separately confirmed live.
- **FAILED CHECK** — the independent curl pass returned a non-2xx status (404/403/406/503/timeout) on this exact URL. Does not necessarily mean the resource is gone — often means archive.org rate-limiting, a moved page, or a check-time transient — but must be **re-verified before the app depends on it**.
- **UNVERIFIED** — not covered by the curl pass; status is carried over from the research docs' own fetch notes (which may themselves be partial/secondary-source).

**Golden rule inherited from the spec:** Quran text is never hand-typed. Every resource must be free + openly licensed, or link-only (never re-hosted).

## Cross-cutting build rules (repeated from the spec, load-bearing for every section above)

1. **Never hand-type Quran text.** Every Arabic string in every lesson/drill file must trace to Tanzil (via direct fetch or the quran.com/alquran.cloud mirrors) and be copy-verified, not retyped from any research doc or blog.
2. **Never re-host audio, video, or proprietary fonts/PDFs.** Stream/link only. The one exception is the KFGQPC font family and Amiri/Noto/Scheherazade, which are explicitly licensed for redistribution as unmodified files (self-hosting the verbatim binary is fine; modifying/subsetting it is not, for the KFGQPC family specifically).
3. **Bake external API data into static build-time content files.** No Quran API should be called live at runtime in the shipped static Next.js app.
4. **Every audio reference and every Quran string needs a scripted resolution check** before shipping each lesson (per the spec's own QA requirement) — this manifest's VERIFIED OK / FAILED CHECK statuses are a snapshot from 2026-07-19 and must be re-run at implementation time, not trusted indefinitely.
5. **Document the color-legend choice explicitly** (§7) before any Phase 3 slide ships — the sources disagree, so the course's own choice must be written down, not left implicit.
